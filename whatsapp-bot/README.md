# اتصال زنده به گروه‌های واتساپ سازنده‌ها

این یک سرویس **همیشه-روشن** جدا از بقیه پروژه است. برخلاف `scripts/monitor-websites.js` (که روزی یک‌بار توسط GitHub Actions اجرا و بسته می‌شود)، این برنامه باید ۲۴ ساعته روشن بماند تا به واتساپ وصل بماند و پیام‌های گروه‌ها را لحظه‌ای بخواند.

## این چطور کار می‌کند
1. با اسکن یک QR (فقط یک‌بار)، به یک شماره واتساپ وصل می‌شود — دقیقاً مثل «افزودن دستگاه جدید» در واتساپ خودتان.
2. به پیام‌های تمام گروه‌هایی که آن شماره عضوشان است گوش می‌دهد.
3. وقتی پیامی در یکی از گروه‌های سازنده‌ها می‌آید، متنش را با Claude بررسی می‌کند که آیا خبر مهمی (لانچ پروژه، تغییر قیمت و...) هست یا نه.
4. اگر بود، نتیجه را در `data/projects.json` (در ریپازیتوری گیت‌هاب شما) ثبت و commit/push می‌کند — همان فایلی که سایت شما و مانیتور سایت‌ها هم استفاده می‌کنند.

## ⚠️ نکته امنیتی مهم — شماره واتساپ
این روش **غیررسمی** است (کتابخانه Baileys، نه API رسمی متا) و برخلاف قوانین استفاده واتساپ محسوب می‌شود. ریسک محدود/مسدود شدن شماره وجود دارد، هرچند برای گوش‌دادن صرف (بدون ارسال پیام انبوه) این ریسک معمولاً کم است.
**پیشنهاد قوی: یک شماره واتساپ جداگانه و مخصوص همین کار بسازید** (یک سیم‌کارت ارزان یا شماره مجازی کافی است) و آن را عضو گروه‌های خبری سازنده‌ها کنید — نه شماره اصلی خودتان.

## چیزهایی که لازم دارید

| متغیر محیطی | توضیح |
|---|---|
| `ANTHROPIC_API_KEY` | کلید API از [console.anthropic.com](https://console.anthropic.com) |
| `GITHUB_TOKEN` | یک Personal Access Token گیت‌هاب با دسترسی نوشتن به این ریپازیتوری (پایین توضیح داده شده) |
| `GITHUB_REPO` | نام ریپازیتوری، مثلا `mozhgankia/Client_tracker` |
| `GIT_BRANCH` | برنچی که باید آپدیت شود (پیش‌فرض: `Main`) |
| `GIT_USER_NAME` / `GIT_USER_EMAIL` | نام/ایمیلی که در commit ها ثبت می‌شود (اختیاری، مقدار پیش‌فرض دارد) |

### ساخت GITHUB_TOKEN
1. گیت‌هاب → عکس پروفایل → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Repository access: فقط همین ریپازیتوری (`Client_tracker`) را انتخاب کنید.
3. Permissions → **Contents**: **Read and write**.
4. توکن ساخته‌شده را کپی کنید (فقط یک‌بار نمایش داده می‌شود).

## اجرا کجا؟ (باید ۲۴ ساعته روشن بماند)

### گزینه ۱ — Railway (پیشنهادی، ساده‌ترین برای شروع)
1. در [railway.app](https://railway.app) حساب بسازید و «New Project» → «Deploy from GitHub repo» → همین ریپازیتوری را انتخاب کنید.
2. در تنظیمات سرویس، **Root Directory** را روی `whatsapp-bot` بگذارید.
3. متغیرهای محیطی بالا را در بخش **Variables** وارد کنید.
4. یک **Volume** بسازید و آن را به مسیر `/app/auth_info` وصل کنید (این پوشه باید بین ری‌استارت‌ها باقی بماند، وگرنه هر بار باید دوباره QR بزنید).
5. Deploy کنید و در تب **Logs** منتظر بمانید تا QR کد چاپ شود؛ با گوشیِ شماره‌ی اختصاصی اسکن کنید (واتساپ ← تنظیمات ← دستگاه‌های متصل ← اتصال دستگاه).

### گزینه ۲ — یک VPS که از قبل دارید
```bash
cd whatsapp-bot
npm install --omit=dev
export ANTHROPIC_API_KEY=...
export GITHUB_TOKEN=...
export GITHUB_REPO=mozhgankia/Client_tracker
npm install -g pm2
pm2 start index.js --name whatsapp-monitor
pm2 logs whatsapp-monitor   # برای دیدن QR در اولین اجرا
pm2 save && pm2 startup     # تا بعد از ری‌استارت سرور هم خودش دوباره بالا بیاد
```
مطمئن شوید `git` روی سرور نصب است (`git --version`).

### گزینه ۳ — روی کامپیوتر خودتان (فقط برای تست)
```bash
cd whatsapp-bot
npm install
ANTHROPIC_API_KEY=... GITHUB_TOKEN=... GITHUB_REPO=mozhgankia/Client_tracker npm start
```
تا وقتی ترمینال باز و کامپیوتر روشن است کار می‌کند؛ برای استفاده واقعی روزانه گزینه ۱ یا ۲ را انتخاب کنید.

## اضافه‌کردن هر گروه به تنظیمات
وقتی پیامی از یک گروه ناشناس بیاید، برنامه در لاگ چاپ می‌کند:
```
ℹ️  پیام از گروه ناشناس دریافت شد — برای پیگیری با priority درست، این را به config/developers.json اضافه کنید:
    نام گروه: پروژه‌های سازنده الف
    whatsapp_group_id: 12036304xxxx@g.us
```
این `whatsapp_group_id` را در فیلد مربوطه‌ی همان سازنده در `config/developers.json` کپی کنید و commit/push کنید. تا قبل از آن هم اخبار آن گروه با اولویت پیش‌فرض (کمترین اولویت) ثبت می‌شود تا چیزی از دست نرود.

## هزینه و نکات
- هر پیام متنی گروه یک بار به Claude فرستاده می‌شود — برای گروه‌های خیلی پرحرف ممکن است هزینه API بالا برود. اگر لازم شد، می‌توان فیلتر کلمات کلیدی قبل از فراخوانی Claude اضافه کرد.
- تغییرات با کمی تأخیر (پیش‌فرض ۳۰ ثانیه بعد از آخرین پیام) دسته‌جمعی commit/push می‌شوند تا تعداد commit ها زیاد نشود.
- فقط پوشه `auth_info/` نیاز به ماندگاری (persistent volume) دارد؛ بقیه چیزها با هر ری‌استارت دوباره ساخته می‌شوند.
